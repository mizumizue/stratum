# 仕様深度ループ（spec depth）

調査稿はあるのに、権限差・可変境界・主ワークフローの決め事が浅い／落ちない、を潰す。成果は深さメモまで。L2/L3・PBI・実装には進まない。

型: **EO**（詳細: `.cursor/skills/loop/author-loop-skill/patterns/EO.md`）

## 呼び出し

| 起動 | 人間との接点 |
|------|----------------|
| 上位オーケストレータの1工程 | **なし**。テーマ・`STATE_DIR`・入力パス・打ち切りは指示書に従う。判断はオーケストレータに任せる |
| ユーザーが単体起動 | 起動文の指示だけ使う。以降は確認しない。薄い項目は AI が決め、聞かない |

## ペルソナ

既定は空。付けない。

## kernel

| 柱 | 内容 |
|----|------|
| Verifier | `STATE_DIR/spec-depth.md` に対し、下表 **D1–D6 がすべて Yes** |
| State | `STATE_DIR/spec-depth.md`（最終稿）、`STATE_DIR/loop-log.md`（各周の Verifier）。`STATE_DIR` 未指定時は入力 brief と同ディレクトリ、それも無ければ `research/<topic-slug>/`。実証ループから呼ばれたときは指示書の run 配下 |
| Stop | D1–D6 全 Yes、または改稿 **最大 3 周**。入力 brief（または指示書が渡す同等）が無い／読めないときは即停止し `loop-log.md` に理由。L2/L3・実装へ進まない |
| Leash | 触ってよい: `STATE_DIR/`、入力 brief／指示書の読み取り、不足を埋める軽い Web 再調査（brief 本体の本改稿は調査工程の範囲）。触るな: `specs/` `pbl/` `issues/` `product/` `agents/` への書き込み、D1–D6 の緩和・書き換え、起動後のユーザー確認、秘密情報の記載、可変境界ラベルの決め打ち |

### Verifier（D1–D6）

| ID | Yes の条件 |
|----|------------|
| D1 | sector brief（または同等）と、起動／指示書上の **システム狙い**（誰向け・何の主ジョブ）への参照がある |
| D2 | 役 ≥2、各主ジョブ1文、権限差の表（見える／できる／できない）がある |
| D3 | 可変境界が **当該システム向けに命名**され、可変／固定の区別がある（外部から持ち込んだ境界ラベルだけで埋めない） |
| D4 | 主WFの決定項目と状態遷移 ≥2 がある。時間・量・承認は記述、または非該当＋理由 |
| D5 | 概念 ≥5、採用と見送り＋理由があり採用 ≥1 |
| D6 | 上記が調査の帰結として辿れ、一般論や単一フォーム CRUD だけで埋まっていない |

1つでも No なら不合格。Generator はルーブリックを書き換えない。

## 手順

1. 指示書または起動文からシステム狙い・`STATE_DIR`・入力 brief パスを固定する。brief が無ければ Stop（即停止）。ユーザーに聞かない  
2. Generator: brief とシステム狙いから `spec-depth.md` を書く／直す。最低欄は actors／権限表、可変境界（命名＋可変／固定）、主WFの決定項目と状態、概念一覧、採用／見送り  
3. Evaluator: D1–D6 を Yes/No し、欠陥リストを `loop-log.md` に追記する  
4. 不合格かつ周回 < 3 なら欠陥だけを入力に手順2へ戻る  
5. Stop で止め、`STATE_DIR` と D 結果（または未達）を短く報告する。オーケストレータ配下なら指示書の戻り先のみ  

## 完了基準

- [ ] Verifier が Stop 条件を満たす（全 Yes、または 3 周打ち切り／brief 欠落下の未達記録）  
- [ ] Leash を破っていない  
- [ ] State の場所を報告した  
- [ ] ユーザーへの途中確認をしていない（単体起動の起動文のみ例外）
