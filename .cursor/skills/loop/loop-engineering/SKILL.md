# ループエンジニアリング（1工程）

1つの仕事を **やって → チェック → 直す** で回す。ユーザーに型名（GV 等）は選ばせない。

型カタログと選定表: [`../author-loop-skill/patterns/`](../author-loop-skill/patterns/)（必ず `SELECTING.md` を読む）。

## 先導語

- **kernel** — Verifier / State / Stop / Leash の4柱  
- **leash** — チェック役を壊させない拘束  

## ペルソナ

既定は **空**。ユーザーが明示したときだけ、注意の向きとして注入する。Verifier・Stop・Leash は変えない。

## 手順

### 1. ヒアリング

目的・困りごと・「どうなったら成功か」を聞く。事実は調べてよい。決定はユーザーに聞く。  
一度に質問は1つ（推奨つき）。型のメニューは出さない。

**完了:** 成功条件が1文で言える。

### 2. 型の提案 → 一言承認

`patterns/SELECTING.md` に従い型を1つ選ぶ。  
平易な言い方＋理由を示し、承認を待つ。却下なら別型を1つ再提案。

**完了:** 型IDとユーザー承認がある。

### 3. kernel を固定する

選んだ型の `patterns/<ID>.md` を読み、次を具体化する。

| 柱 | 決めること |
|----|------------|
| Verifier | 合否の見方（コマンド、ルーブリック、ユーザー確認など） |
| State | 成果物・ログの置き場 |
| Stop | 終了条件と上限 |
| Leash | 触ってよい範囲／触ってはいけないチェック役 |

ユーザーに平易に確認する（技術詳細のメニューで圧倒しない）。

**完了:** 4柱が書き出されている。

### 4. ループを回す

型の1周手順に従う。各周の終わりに Verifier を見る。Stop まで続ける。

**完了:** Stop を満たすか、ユーザーが中断した。

### 5. 締め

何が通ったか、残課題、State の場所を短く報告する。
