# 生成スキル検品（工場の Verifier）

`author-loop-skill` / `author-loop-workflow` が生成した `SKILL.md` を、ユーザーに「完了」と伝える前に通す。  
1項目でも落ちたら **修正して再検品**。パスするまで工場は終わらない。

曖昧語（「適切に」「高品質」「必要に応じて」だけ）は不合格。

---

## A. 工程スキル検品（`author-loop-skill`）

生成物を開き、次をすべて確認する。

### A1. 機械的

- [ ] `{{` `}}` プレースホルダが残っていない  
- [ ] frontmatter に `name` / `description` / `disable-model-invocation: true` がある  
- [ ] `name` は小文字・数字・ハイフンのみ  
- [ ] 型IDが実在する（`patterns/<ID>.md` がある）  
- [ ] ペルソナ既定が空である旨が本文にある  

### A2. kernel — Verifier（最重要）

次の **いずれか1つ**を満たし、かつ合否の見方が文章で追える。

- [ ] **実行可能:** 具体的なコマンド、テスト名、またはスクリプトパスが書いてある  
- [ ] **人間ゲート:** 「ユーザーが確認する質問文」が1文で書いてある（GRILL/一部EO向け）  
- [ ] **ルーブリック:** 合否項目が箇条書きで、各項目が Yes/No 判定できる  

不合格例: 「品質を確認する」「うまく動くか見る」だけ。

### A3. kernel — State / Stop / Leash

- [ ] **State:** 成果物またはログの置き場がパス／ファイル名レベルで具体  
- [ ] **Stop:** 終了条件が判定可能で、回数または時間の **上限**がある  
- [ ] **Leash:** 「触ってよいもの」と「触ってはいけないチェック役」が両方ある  

### A4. 手順

- [ ] 手順が順序付きである  
- [ ] 「ループを回す」に相当するステップがある  
- [ ] スキル全体の完了基準がチェックリストになっている  

**工程スキル検品の完了:** A1–A4 がすべてチェック済み。落ちた項目と修正内容を控える。

---

## B. ワークフロースキル検品（`author-loop-workflow`）

### B1. 機械的

- [ ] プレースホルダなし  
- [ ] `disable-model-invocation: true`  
- [ ] `ORCHESTRATION.md` へのポインタ、または全文同梱がある  
- [ ] `STAGE-EXEC.md` へのポインタがある（または同等の実行手段ルールが本文にある）  
- [ ] 本文に「指揮者は実作業しない」「工程は SubAgent」が明示されている  
- [ ] ペルソナ既定が空（または工程表で `—`）である  

### B2. 工程表（全行）

各工程行について:

- [ ] 工程名がある  
- [ ] 入力（前成果物または開始条件）がある  
- [ ] 出力パスまたは成果物名がある  
- [ ] **実行手段**が `skill:<name>` または `loop-eng` である  
- [ ] `loop-eng` なら型IDが実在する。`skill:` なら型は空/`—` でよい（併記するなら実在すること）  
- [ ] `skill:` なら参照スキルの `SKILL.md` が **提案時点で**存在する（実行時欠落はフォールバックで扱う）  
- [ ] `skill:` なら **フォールバック型**が実在する（強く推奨。欠ける場合は本文に「欠落時は SELECTING＋一言承認」と明記）  
- [ ] Verifier がある — スキル時は「skill 完了＝ゲート」等のゲート文、loop-eng 時は A2 同水準  
- [ ] Stop に上限がある  
- [ ] 本文または参照に「スキル利用不可時は loop-eng 代用」がある（`STAGE-EXEC.md` ポインタ可）  

1行でも欠ければ不合格。

### B3. つなぎ・指揮

- [ ] 前工程ゲート通過まで次へ進まない、と書いてある  
- [ ] 巻き戻しは提案＋一言承認、と書いてある  
- [ ] 指揮者の手順に「指示書を書いて SubAgent に渡す」がある  
- [ ] 指揮者が成果物の中身を書く手順が **無い**  
- [ ] 作業者が実行手段（スキルまたは loop-eng）に従う旨がある  

### B4. スキル全体の完了基準

- [ ] 指揮者非実作業・ゲート記録・最終成果物パスの報告が完了基準に含まれる  

**WFスキル検品の完了:** B1–B4 がすべてチェック済み。

---

## 検品ログ（ユーザーへの報告）

完了時に短く出す:

1. 検品対象パス  
2. A または B の全項目パス（落ちて直した項目があれば「修正→再検品パス」）  
3. Verifier を一文で再掲（実行コマンドまたは人間ゲート文）
