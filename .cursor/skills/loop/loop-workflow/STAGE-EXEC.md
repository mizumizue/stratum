# 工程の実行手段（スキル / loop-eng / ペルソナ）

`loop-workflow` と `author-loop-workflow` の単一の情報源。  
創造的か機械的かでは切らない。

## 選び方（この順）

1. **再利用したい手順があるか？**（または既存スキルが工程目的に近いか）  
   → **具体ループスキル**を割り当て  
2. なければ、合否・手順の骨格は言えるか？  
   → **`loop-engineering` + 型**（型は `SELECTING.md`）  
3. 方針が割れているだけか？  
   → その工程は **GRILL**（または前段で潰す）  
4. それでも「見る順番だけ変えたい」が残るときだけ  
   → **薄いペルソナ**（注意の向き）。既定は **空**。Verifier は変えない  

## フォールバック（必須）

`skill:<name>` を割り当てていても、実行時に次なら **loop-eng に切り替える**。

使えない例:

- `SKILL.md` が無い／読めない  
- スキルが無効化・削除・パス切れ  
- 前提ツールや環境が無く、スキル手順が実行不能  
- 作業者がスキルを適用できずブロックした  

切り替え手順:

1. ゲートログに「skill 利用不可 → loop-eng 代用」と理由を1行残す  
2. 工程表の **フォールバック型**（事前に書いておく）で `loop-engineering` を回す  
3. フォールバック型が空なら、目的から `SELECTING.md` で型を1つ選び、平易に一言承認してから回す  
4. Verifier は表のゲート文を維持。スキル完了前提の文面なら、loop-eng 用の具体 Verifier に読み替えてログに残す  

スキルありきで止まらない。**動かすことが優先**で、代用したらユーザーに短く報告する。

## 工程表の欄

| 欄 | 必須 | 内容 |
|----|------|------|
| 実行手段 | 必須 | `skill:<name>` または `loop-eng` |
| 型 | loop-eng のとき必須。スキル時は省略可 | GV / RGR / DIAG / RALPH / EO / GRILL |
| フォールバック型 | **skill のとき推奨（強く推奨）** | スキル不可時に使う型。無ければ実行時に SELECTING＋一言承認 |
| ペルソナ | 既定空 | 注意の向きだけ。空なら欄は `—` |
| Verifier | 必須 | ゲート用。スキル時は「`<skill>` 完了＝ゲート」（＋必要なら引用）。loop-eng 時はコマンド／Yes-No／確認質問 |
| Stop | 必須 | 上限つき |

## 工場・指揮者の提案手順

1. 工程の目的と成功条件を聞く（実行手段のメニューは出さない）  
2. プロジェクト `.cursor/skills/` と、あれば `~/.cursor/skills/` を見て、description が近いスキルを最大2–3候補  
3. 再利用しそう／候補が十分近い → スキルを1つ推奨し、**フォールバック型も一緒に提案**。否則 loop-eng＋型を推奨  
4. 平易な言い方で示し、一言承認  
5. ペルソナは聞かれたとき・明確に視点が必要なときだけ提案。それ以外は空  

## 作業者への指示書

- **skill:** 該当 `SKILL.md` を読む。読めない／実行不能なら **即フォールバック**（上節）し、loop-eng で工程を回す  
- **loop-eng:** `loop-engineering` と指定型の `patterns/<ID>.md` に従う  
- ペルソナが空でなければ、注意の向きとしてだけ注入（完了条件は変えない）  
- フォールバックしたら、完了報告に「代用した」旨と使った型を含める
