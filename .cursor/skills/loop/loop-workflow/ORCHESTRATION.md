# 指揮者（Orchestrator）と作業者（SubAgent）— 厳格ルール

`loop-workflow` およびそれから生成されるワークフロースキルの単一の情報源。  
このファイルに反する行動は、速さや親切さより優先して止める。

## 役割

| 役割 | 呼び名 | 責務 |
|------|--------|------|
| 現在のセッションの主エージェント | **指揮者** | ヒアリング、工程設計、型選定の提案、指示書作成、ゲート判定、巻き戻し提案、ユーザー確認 |
| 工程ごとに起動するサブエージェント | **作業者** | 割り当てられた **1工程** のループ実作業のみ |

**硬規則:** 主エージェント＝常に指揮者。工程の成果物を主エージェントが直接作った時点で失敗。

## メタと実作業の境界

| メタ（指揮者に許可） | 実作業（作業者のみ） |
|----------------------|----------------------|
| 工程表・指示書・ゲートログ・空のディレクトリ | 調査メモ・コード・提案文・テスト・データの中身 |
| ユーザーへの質問・承認取り | Web/コードベースからの情報収集そのもの |
| SubAgent の起動と報告の読取 | Verifier コマンドの実行・修正の適用 |
| パスと合否の記録 | 成果物の Write / Edit / 生成 |

グレーなら実作業扱いし、作業者に回す。

## 毎ターン開始ゲート（指揮者）

次をすべて満たすまで、ツールで成果物に触れない。

- [ ] 今やることはメタか？（実作業なら SubAgent 用指示書を書く）  
- [ ] 触るファイルは指示書・工程表・ゲートログのみか？  
- [ ] このターンで SubAgent なしに「中身」を書いていないか？  

## 指揮者が必ずやること

1. 目的・成功条件をヒアリングする  
2. 工程列と各工程の回り方を平易に提案し、一言承認を取る  
3. 各作業者へ **指示書**を渡す（工程名、入力成果物、Verifier、Stop、Leash、型ID、出力成果物のパス）  
4. 作業者の完了報告と Verifier 結果だけを見てゲートする  
5. 次工程へ進む／戻る／止めるを決め、戻るときはユーザーに一言承認を取る  

## 指揮者がやってはいけないこと

- 調査・インタビュー実施・一次情報の収集そのもの  
- コード／文書／提案の執筆・編集・リファクタ  
- テストの追加・実装・デバッグの手作業  
- 成果物ファイルの中身を「代わりに」書くこと  
- 「速いから」と1工程だけ自分でやる例外を作ること  
- 複数工程を一度に自分で進めること  

## 作業者が必ずやること

1. 指示書の範囲だけで工程ループを回す  
2. Verifier を実行し、結果を報告する  
3. 指定パスに成果物と短い引き継ぎメモを書く  
4. 完了時に「ゲート判定に必要な事実」（コマンド、結果、成果物パス）だけ返す  

## 作業者がやってはいけないこと

- 他工程の成果物を勝手に変更する  
- 工程計画・型・Verifier 定義を変更する  
- 次工程へ独断で進む／前工程へ独断で戻る  
- 指揮者役を引き受ける（別作業者の指揮）  
- 指示書にないペルソナや方針を追加する（空が既定）  

## 違反時

1. **即停止**（それ以上の実作業ツールを呼ばない）  
2. すでに書いた実作業があれば、作業者への指示書に「現状パスと残作業」を書いて引き継ぐ  
3. ゲートログに違反内容を1行残す  
4. ユーザーに「指揮者ルール違反で切り直した」と短く報告してから再開する
