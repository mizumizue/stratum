# RGR — Red–Green–Refactor

出典: Kent Beck の TDD。実装スキル化の代表は mattpocock/skills の `/tdd`。

## 1周

1. 失敗するテストを1つ書く（Red）  
2. テストが実際に赤になることを確認する  
3. 通す最小実装をする（Green）  
4. 構造を整える（Refactor）。テストは緑のまま  
5. 次の薄片へ  

## kernel への写像

| 柱 | 典型 |
|----|------|
| Verifier | テストランナー（該当テスト） |
| State | テストファイル、実装、緑の証明ログ |
| Stop | 受け入れ条件を満たす薄片が揃ったとき |
| Leash | テストを実装の都合で骨抜きにしない。モックでバグ経路を消さない |

## 向く目的

機能追加・改修で、自動テストが書ける領域。
