# 機能 PRD テンプレ（Source）

`specs/source/<feature-slug>/spec.md` 用。

```markdown
# <Feature 名>

Status: ready-for-agent

## 課題（Problem Statement）

ユーザー視点で直面している問題。

## 解決策（Solution）

ユーザー視点での解決策。

## ユーザーストーリー（User Stories）

1. <役割>として、<機能>が欲しい。なぜなら <便益> だから

## 実装上の決定（Implementation Decisions）

- 構築 / 変更するモジュール
- 変更するモジュールのインターフェース
- アーキテクチャ上の決定
- 具体的なインタラクション

特定のファイルパスやコードスニペットは含めない（すぐ古くなる）。
例外: プロトタイプが散文より正確に決定を表すスニペットは要点だけインラインし、由来を短く記す。

## テスト上の決定（Testing Decisions）

- 良いテストとは何か（外部振る舞いだけを試し、実装詳細は試さない）
- どのモジュールをテストするか
- テストの先行事例（コードベース内の類似テスト）

## スコープ外（Out of Scope）

この仕様の対象外とする事項。

## 補足（Further Notes）

機能に関するその他のメモ。sandbox / 実装パスを残すならここ（L2/L3 には書かない）。
```
