# Audit (Stratum / V-Model)

仕様（`docs/`）と実装（`src/`）、およびテスト検証結果（`reports/test-results.json`）の乖離や充足度を機械的かつ客観的に監査・点検する。

主成果物は **人間判断用の指摘リスト**、および **Stratum 地層分析レポート**。

## 監査の観点

1. **Gap（仕様と実装の乖離）**:
   - `docs/` に定義されている要件・契約が実装されているか。
   - `docs/test-cases/` に定義されたテストケースに対応するテストコードが存在し、実行されているか。
2. **Conform（過剰設計・拡大解釈）**:
   - 仕様に書かれていない独断の実装、不要に肥大化した抽象化がないか。
3. **Traceability & Stratum Sufficiency（トレーサビリティと地層健全性）**:
   - `NEED` から `TC` までのリンクが途切れていないか（孤立ノードがないか）。
   - テスト地層密度（Unit / ITa / ITb / ST / UAT）がアンチパターン（逆ピラミッドや砂時計型）に陥っていないか。
4. **ADR-0006 遵守（客観的事実の検証）**:
   - `docs/test-cases/` に LLM や人間による作文エビデンスが混入していないか。
   - テスト結果は決定論的に `reports/test-results.json` から生成されているか。

## ステップ

1. **静的ドキュメント・製品コード静的検査を実行する**:
   ```bash
   npm --prefix src run lint       # FW仕様ドキュメントスキーマ検査
   ./bin/stratum lint-product      # 製品コード（多言語）の静的解析・リンター
   ```
2. **Stratum 地層・トレーサビリティ分析を実行する**:
   ```bash
   ./bin/stratum report
   ./bin/stratum matrix
   ```
3. **テスト実行と客観レポート検証を行う**:
   ```bash
   npm --prefix src test
   ```
4. **指摘リストと次アクションをまとめる**:
   - 発見された不整合・孤立ノード・未実施テストについて、仕様修正／実装修正／テスト追加のいずれの対応をとるべきかを整理する。

## 出力フォーマット

```markdown
## 仕様・実装乖離 (Gap & Conform)
- [ ] ...

## トレーサビリティ・地層健全性 (Stratum Analysis)
- 追跡スコア / 孤立ノード: ...
- ピラミッド充足度評価: ...

## テスト実測検証 (Objective Evidence)
- 合格テスト数 / 失敗 / 未実行: ...

## 次のアクション候補
- [仕様修正] ...
- [実装修正] ...
- [テスト追加] ...
```

## セッション完了

客観的な監査結果、指摘リスト、および次アクションが提示されている。
