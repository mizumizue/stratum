# Spike (Stratum / V-Model)

あいまいな要求や新技術の検証を **プロトタイプや試し書きで触って明確化する**（要件スパイク）。

本プロジェクトの正本は `docs/`（V-Model 体系: NEED, REQ, SPEC, DSN, ADR, QA, TC）です。
Spike 中は確定した仕様として `docs/` にコミットせず、仮説検証用のコードやメモを作成します。

## ステップ

1. **疑問を1つに絞る**:
   - 何が分からないのか、どの技術・インターフェース・要件が不確実なのかを一文で定義する。
2. **スパイク検証を行う**:
   - 一時的なスクリプト、プロトタイプ、またはテストを作成して動かし、動作特性や実現可能性を確認する。
3. **学習事項を整理する**:
   - 得られた知見、制約、失敗したアプローチをメモに残す。
4. **Specify（仕様化）へ進む**:
   - 疑問が解消されたら、得られた知見をもとに **`/specify`** へ移行し、`docs/needs/` や `docs/requirements/` に正規の仕様として記述する。

## セッション完了

疑問に対する結論が得られ、学習事項が整理されている（または `/specify` で正式仕様化に着手する準備ができている）。
