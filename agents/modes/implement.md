# Implement (Stratum / V-Model)

`docs/` に定義された仕様（REQ / SPEC / DSN）に従い、**TDD（テスト駆動開発）** で実装を推進する。
コードの都合で仕様を曲げたり、ツールの都合で実装構造を歪めたりしない。
また、**`src/` 配下の製品コードは特定のアーキテクチャや言語に限定されず、プロダクト自体の設計指針には一切関わらない（ADR-0008）**。仕様（What）を充足する最小限のコード（How）を製品自体の設計方針に沿って実装する。

## 基本原則

1. **仕様ファースト**:
   - 必ず対象となる `docs/`（REQ / SPEC / DSN / TC）を確認してから着手する。
2. **赤 → 緑 → リファクタリング (TDD)**:
   - 先にテスト（失敗するテスト）を書き、そのテストを通すための最小限の実装を行う。
3. **客観的エビデンス（ADR-0006）**:
   - テスト結果は Markdown 文書への作文ではなく、テストランナーが出力する `reports/test-results.json` を通じて客観的に証明する。

## ステップ

1. **対象仕様を確認する**:
   - `docs/` 配下の関連ドキュメント（REQ, SPEC, DSN, TC）を特定し、合意された公開インターフェースと受入条件を確認する。
2. **テストコードを作成する（Red）**:
   - `tests/` 配下に公開インターフェースを対象とするテストを作成し、失敗することを確認する。
3. **最小実装を行う（Green）**:
   - `src/` 配下にテストを通過させるための必要最小限のコードを実装する。
4. **構造衛生とリファクタリング**:
   - 重複の排除、命名の改善、関心の分離を行う。テストがすべて緑であることを維持する。
5. **テスト実行と客観レポート生成**:
   - テストスイートを実行し、全テスト合格とレポート更新を確認する。
   ```bash
   npm --prefix src test
   ```

## セッション完了

関連テストがすべて緑（Pass）になり、型検査（`npm --prefix src run typecheck`）およびリント（`npm --prefix src run lint`）に違反がない。
